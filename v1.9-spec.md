## 2. Student practice — auto-rotation

### Current behaviour
Student sees a `domain-tiles` grid (Vocab / VR tiles) and manually picks a domain before each session.

### v1.9 behaviour
Student sees a single **"Practice →"** button. The app picks the domain automatically.

### Algorithm — `pickDomain(leitnerBoxes, vrLeitnerBoxes, maxDifficulty, sessionHistory)`
```
vocabDue = getDueWords(leitnerBoxes, maxDifficulty).length
vrDue    = getDueVRQuestions(vrLeitnerBoxes, maxDifficulty).length

if vocabDue === 0 && vrDue === 0 → show "All caught up" state, no session
if vocabDue === 0 → pick "vr"
if vrDue === 0    → pick "vocab"

otherwise:
  lastDomain = sessionHistory.at(-1)?.domain ?? "vocab"
  if lastDomain === "vocab" → pick "vr"   (strict alternation)
  else → pick "vocab"
```

Strict alternation is the simplest implementation that ensures VR gets equal airtime alongside vocab. No weighting config needed in v1.9 (weights are the tutor-controlled feature deferred to a later version).

### Code changes
- **Remove:** the `domain-tiles` grid JSX from the student practice tab
- **Remove:** the `activeDomain` state (or simplify to derived value from `pickDomain`)
- **Add:** `pickDomain()` helper function (pure, testable)
- **Change:** The "Practice →" button calls `pickDomain()` and sets `activeDomain` + `setPractising(true)` in one step
- **Keep:** `VocabSession` and `VRSession` as separate components — no merging needed

The student still sees domain-labelled session results in Recent Sessions (emoji prefix already in place).

## 3. New VR question types

### 3a. Antonym pairs

**Source:** `VOCAB_BANK` entries with `antonyms` arrays (nearly all 731 words qualify)

**Schema:**
```js
{
  id: "vr-ant-abate",         // stable — tracks in Leitner
  type: "antonym_pair",
  word: "abate",
  correct: "intensify",       // antonyms[0] (or random pick from antonyms array)
  distractors: ["diminish", "subside", "lessen"],  // 3 from synonyms array — plausible wrong answers
  difficulty: 3,              // inherited from VOCAB_BANK entry
}
```

**Generation — `buildAntonymBank()`**
```
for each word in VOCAB_BANK:
  if word.antonyms.length === 0 → skip
  correct = random pick from word.antonyms
  distractors = take 3 from word.synonyms (shuffled); if < 3 synonyms, fill from other words' antonyms
  push { id: "vr-ant-" + word.word, type: "antonym_pair", word, correct, distractors, difficulty: word.difficulty }
```

Call `buildAntonymBank()` once at module level — same pattern as `VR_BANK` constant.  
Result stored as `ANTONYM_BANK` constant.

**Leitner tracking:** uses `vr-ant-[word]` key in `vrLeitnerBoxes`. Tracked identically to existing VR_BANK items. Include in `getDueVRQuestions()`.

**Display:**
```
Choose the word MOST OPPOSITE in meaning to:

  ┌──────────────┐
  │   ABATE      │
  └──────────────┘

  ○ diminish   ○ intensify   ○ subside   ○ lessen
```

### 3b. Synonym pairs

**Source:** Same `VOCAB_BANK` entries, using `synonyms` arrays.

**Schema:**
```js
{
  id: "vr-syn-abate",
  type: "synonym_pair",
  word: "abate",
  correct: "diminish",        // random pick from synonyms array
  distractors: ["intensify", "escalate", "worsen"],  // from antonyms — plausible wrong answers
  difficulty: 3,
}
```

**Generation — `buildSynonymBank()`** — same pattern as antonym bank.

**Leitner tracking:** `vr-syn-[word]` key in `vrLeitnerBoxes`. Include in `getDueVRQuestions()`.

**Display:**
```
Choose the word CLOSEST in meaning to:

  ┌──────────────┐
  │   ABATE      │
  └──────────────┘

  ○ intensify   ○ diminish   ○ increase   ○ worsen
```

### 3c. Letter sequences

**Generation — `generateLetterSequence(difficulty)`**

These are generated fresh on each question render. Not tracked in Leitner.

Patterns by difficulty band:

| Difficulty | Patterns |
|---|---|
| 1 | +1, +2 (e.g. C E G I → K) |
| 2 | +3, -1, -2 (e.g. Z X V T → R) |
| 3 | Alternating step (e.g. A C B D C E → D); interleaved two sequences |
| 4–5 | Two-rule sequences (e.g. +2 then +3 alternating) |

**Algorithm:**
```
pick a pattern based on difficulty
pick a random start letter (A–Z, ensuring the sequence stays in A–Z)
generate 4-letter sequence
correct = next value in the sequence
distractors = 3 plausible wrong letters (adjacent letters ±1 from correct, random letter)
shuffle all 4 options
```

**Schema (runtime only, not stored):**
```js
{
  id: null,                   // not tracked
  type: "letter_sequence",
  sequence: ["C","E","G","I"],
  correct: "K",
  distractors: ["J","L","M"],
  rule: "+2",                 // used only by AI coaching prompt
  difficulty: 1,
}
```

**Display:**
```
What comes next in this letter sequence?

  C    E    G    I    __

  ○ J   ○ K   ○ L   ○ M
```

---

### 3d. Number sequences

**Generation — `generateNumberSequence(difficulty)`**

Also generated fresh. Not tracked in Leitner.

Patterns by difficulty band:

| Difficulty | Patterns |
|---|---|
| 1 | +2, +3, +5, +10 |
| 2 | ×2, ÷2, alternating add (e.g. +3 +5 +3 +5) |
| 3 | Arithmetic with negative step (−4, −7), or two interleaved sequences |
| 4–5 | Squared terms, Fibonacci-style, multiply then add |

**Algorithm:**
```
pick pattern and params based on difficulty
generate starting number (small enough that terms stay < 1000)
generate 4-number sequence
correct = next term
distractors = [correct ± step, correct ± 1, one random plausible number]
shuffle all 4 options
```

**Schema (runtime only):**
```js
{
  id: null,
  type: "number_sequence",
  sequence: [2, 5, 8, 11],
  correct: 14,
  distractors: [12, 13, 16],
  rule: "+3",
  difficulty: 1,
}
```

**Display:**
```
What comes next in this number sequence?

  2    5    8    11    __

  ○ 12   ○ 13   ○ 14   ○ 16
```

## 4. Session composition — how VR questions are assembled

### `getDueVRQuestions(vrLeitnerBoxes, maxDifficulty)` — extended

Current: iterates `VR_BANK` only.

v1.9:
```
due = []
iterate VR_BANK         → add due items as before
iterate ANTONYM_BANK    → add due items (same Leitner logic, key = q.id)
iterate SYNONYM_BANK    → add due items (same Leitner logic, key = q.id)
shuffle(due)
return due
```

### Injecting generated sequences into VRSession

Generated sequences (letter + number) don't sit in a bank — they're created at session start.

In `VRSession`, after building the `queue` from `getDueVRQuestions()`:

```js
const [queue] = useState(() => {
  const due = getDueVRQuestions(vrLeitnerBoxes, maxDifficulty).slice(0, 12);
  // Inject 2 letter + 2 number sequences (or fewer if session is short)
  const seqCount = Math.min(2, Math.floor(due.length / 3));
  const sequences = [
    ...Array.from({ length: seqCount }, () => generateLetterSequence(maxDifficulty)),
    ...Array.from({ length: seqCount }, () => generateNumberSequence(maxDifficulty)),
  ];
  return shuffle([...due, ...sequences]);
});
```

Total session target: ~16 questions (12 Leitner-due + 4 generated). Adjust `slice(0,12)` and seqCount as needed.

### Leitner update — `handleSessionEnd` / `handleAnswer` in VRSession

```js
// In results array, generated questions have id === null
// Only update vrLeitnerBoxes for questions where r.id !== null
results.forEach(r => {
  if (!r.id) return;  // skip generated sequences
  const cur = newVrBoxes[r.id] || { box: 0, lastSeen: 0 };
  newVrBoxes[r.id] = { box: r.correct ? Math.min(cur.box+1,5) : 0, lastSeen: Date.now() };
});
```

## 5. VRSession — rendering changes

### Dispatcher pattern

Replace the current inline render of `q.type === "analogy"` / `q.type === "odd_one_out"` with a dispatcher:

```jsx
function renderVRQuestion(q, selected, handleAnswer) {
  switch (q.type) {
    case "analogy":         return <AnalogyCard q={q} selected={selected} onAnswer={handleAnswer} />;
    case "odd_one_out":     return <OddOneOutCard q={q} selected={selected} onAnswer={handleAnswer} />;
    case "antonym_pair":    return <WordPairCard q={q} selected={selected} onAnswer={handleAnswer} label="MOST OPPOSITE in meaning" />;
    case "synonym_pair":    return <WordPairCard q={q} selected={selected} onAnswer={handleAnswer} label="CLOSEST in meaning" />;
    case "letter_sequence": return <SequenceCard q={q} selected={selected} onAnswer={handleAnswer} />;
    case "number_sequence": return <SequenceCard q={q} selected={selected} onAnswer={handleAnswer} />;
  }
}
```

`WordPairCard` is one component used for both antonym and synonym (distinguished by the `label` prop).  
`SequenceCard` is one component used for both letter and number sequences (item display is the same pattern).

### AI coaching prompts — extended

```js
// In handleAnswer, extend the user prompt construction:
case "antonym_pair":
  user = isCorrect
    ? `Student correctly identified the antonym of "${q.word}" as "${q.correct}". One short celebration (max 10 words):`
    : `Student chose "${opt}" as antonym of "${q.word}". Correct answer: "${q.correct}". Explain why in 1 friendly sentence for a 10-year-old.`;

case "synonym_pair":
  user = isCorrect
    ? `Student correctly identified a synonym of "${q.word}" as "${q.correct}". One short celebration (max 10 words):`
    : `Student chose "${opt}" as a synonym of "${q.word}". Correct answer: "${q.correct}". Explain why in 1 friendly sentence for a 10-year-old.`;

case "letter_sequence":
  user = isCorrect
    ? `Student completed a letter sequence (${q.sequence.join(" ")} → ${q.correct}) correctly. One short celebration:`
    : `Student got a letter sequence wrong: ${q.sequence.join(" ")} → ? Chose "${opt}", correct is "${q.correct}". Rule is "${q.rule}". Explain in 1 sentence for a 10-year-old.`;

case "number_sequence":
  user = isCorrect
    ? `Student completed number sequence (${q.sequence.join(", ")} → ${q.correct}) correctly. One short celebration:`
    : `Student got a number sequence wrong: ${q.sequence.join(", ")} → ? Chose "${opt}", correct is "${q.correct}". Rule is "${q.rule}". Explain in 1 sentence for a 10-year-old.`;
```
